# Café Room and Model Pipeline (Build Step 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the floating stations into one complete toon café: walls,
floor, ceiling, windows, pendant lamps, the back room, and a real brew bar
with a counter and espresso machine. Build the pipeline so the user's
Blender `.glb` models replace any of these pieces with one line each.

**Architecture:** The procedural room lives in `components/cafe/room.tsx`
and `components/cafe/stations/brew-bar.tsx`, built from the same toon kit.
A `Model` component loads a `.glb` from a registry. It gives every mesh the
toon material and an ink outline, and falls back to the procedural piece
when there is no file, while loading, or when loading fails. Pure helpers
(`toonify`, `collectMeshes`, `modelSrc`) are unit-tested in node with real
three objects.

**Tech Stack:** R3F 9.8, drei 10.7 (`useGLTF` with meshopt), three 0.185,
`@gltf-transform/cli` (dev only), vitest 3.

**Spec:** `docs/superpowers/specs/2026-10-11-coffee-shop-portfolio-design.md`
(section 3 "Your Blender → web pipeline", build step 5).

**Base branch:** `feat/cafe-hud`. Branch `feat/cafe-room` from it.

**Decision recorded here:** the spec says the user models the shop in
Blender. The user's `/goal` asks for the café to be finished through to the
full model. This plan builds a complete procedural toon room in code now, so
the café is whole without waiting on Blender. Every procedural piece sits
behind `<Model name=… fallback={…}>`, so a Blender file replaces it with no
other code change. Cost if wrong: the procedural pieces are thrown away
when real models land, which is the intended path anyway.

## Global Constraints

- Room bounds: x from -7 to 7, z from 0 (front, storefront door) to -9.5
  (back wall with a doorway to the roastery); the roastery room spans z
  from -9.5 to -14 and x from -4 to 4. Ceiling at y = 4.
- Toon look: every mesh uses `Toon` and `Ink` from `components/cafe/kit.tsx`.
  Loaded models get `toonify` and `Ink` too.
- Models load with meshopt compression (`useGLTF(src, false, true)`), never
  the Draco CDN decoder.
- Registry names: `"room"`, `"brew-bar"`. While a name has no file, its
  procedural fallback renders.
- A missing or broken `.glb` never breaks the scene: the fallback shows.
- All new three code stays inside the `next/dynamic` scene chunk.
- `/` and the menu modes are untouched. `npm run build` green after each
  task.
- Commits follow `.claude/skills/git-operations/SKILL.md`. **No
  `Co-Authored-By` trailer or attribution footer.** Do not stage
  `lib/particle-shapes.ts` or `.superpowers/`. Never commit `.blend` files.

## Review Focus

1. **A model with multi-material meshes or no material colour:** `toonify`
   must not throw, and keeps colour and texture map when present. Pinned in
   Task 1.
2. **Nested transforms in a loaded model:** world matrices are baked so
   parts land where Blender put them. Pinned in Task 1 (`collectMeshes`
   with a parented, offset mesh).
3. **A registry entry pointing at a missing file:** the fallback renders.
   Pinned in Task 2 by the error boundary.
4. **Camera paths now pass through the walls:** every glide between
   stations must stay inside the room or go through a doorway. Pinned in
   Task 3 with a test that samples `cameraPose` along the whole scroll.
5. **Light count:** six pendant point lights plus the scene lights must not
   tank frame rate. Pinned in Task 3 (lamp lights limited to
   `distance: 6` and `decay: 2`; the quality monitor from step 3b still
   applies).

```ts
// ============================================================
// TOONIFY
// ============================================================
// Loaded Blender models arrive with standard PBR materials. toonify swaps
// each for the café's toon material, keeping colour, texture and
// transparency, so a model needs no special export settings to match the
// shop. collectMeshes flattens a model into meshes with baked world
// matrices, so each can get its own ink outline.
// ============================================================

import {
  Color,
  Matrix4,
  Mesh,
  MeshToonMaterial,
  type BufferGeometry,
  type Material,
  type Object3D,
  type Texture,
} from "three";
import { toonGradient } from "@/components/cafe/materials/toon";

type Colored = Material & { color?: Color; map?: Texture | null };

export function toonify(source: Material | Material[]): MeshToonMaterial {
  const src = (Array.isArray(source) ? source[0] : source) as Colored | undefined;
  const toon = new MeshToonMaterial({
    color: src?.color ? src.color.clone() : new Color("#ffffff"),
    map: src?.map ?? null,
    gradientMap: toonGradient(),
    transparent: src?.transparent ?? false,
    opacity: src?.opacity ?? 1,
  });
  toon.name = src?.name ?? "";
  return toon;
}

export type BakedMesh = { geometry: BufferGeometry; material: MeshToonMaterial; matrix: Matrix4 };

export function collectMeshes(root: Object3D): BakedMesh[] {
  root.updateMatrixWorld(true);
  const out: BakedMesh[] = [];
  root.traverse((obj) => {
    if (obj instanceof Mesh) {
      out.push({
        geometry: obj.geometry,
        material: toonify(obj.material),
        matrix: new Matrix4().copy(obj.matrixWorld),
      });
    }
  });
  return out;
}
```

```tsx
"use client";

// ============================================================
// MODEL
// ============================================================
// Renders a registered Blender model with the toon look and ink outlines,
// or the procedural fallback while there is no file, while it loads, or if
// it fails to load. Meshopt compression only: no external Draco decoder.
// ============================================================

import { useGLTF } from "@react-three/drei";
import { Component, Suspense, useMemo, type ReactNode } from "react";
import { Ink } from "@/components/cafe/kit";
import { collectMeshes } from "@/components/cafe/materials/toonify";
import { modelSrc, type ModelName } from "@/lib/cafe/models";

class ModelBoundary extends Component<{ fallback: ReactNode; children: ReactNode }, { failed: boolean }> {
  state = { failed: false };
  static getDerivedStateFromError() {
    return { failed: true };
  }
  componentDidCatch(error: unknown) {
    console.warn("[cafe] model failed to load, using the built-in piece", error);
  }
  render() {
    return this.state.failed ? this.props.fallback : this.props.children;
  }
}

function Loaded({ src }: { src: string }) {
  const { scene } = useGLTF(src, false, true);
  const meshes = useMemo(() => collectMeshes(scene), [scene]);
  return (
    <group>
      {meshes.map((m, i) => (
        <mesh key={i} geometry={m.geometry} material={m.material} matrix={m.matrix} matrixAutoUpdate={false}>
          <Ink />
        </mesh>
      ))}
    </group>
  );
}

export default function Model({ name, fallback }: { name: ModelName; fallback: ReactNode }) {
  const src = modelSrc(name);
  if (!src) return <>{fallback}</>;
  return (
    <ModelBoundary fallback={fallback}>
      <Suspense fallback={fallback}>
        <Loaded src={src} />
      </Suspense>
    </ModelBoundary>
  );
}
```

```markdown
# Adding a Blender model to the café

The café renders built-in toon pieces until a model file exists. To
replace a piece with your own model:

1. **Model in Blender** with simple shapes. Real-world scale (1 unit =
   1 metre). Apply all transforms (Ctrl+A → All Transforms). Plain colours
   or one texture per material are enough; the café adds the toon shading
   and ink outlines itself.
2. **Match the layout.** The room spans x −7…7 and z 0…−9.5 (front door at
   z 0, back doorway to the roastery at z −9.5), ceiling at y 4. The brew
   bar counter stands around x 5.6, z −3. Keep the origin at the world
   origin so the model lands in place.
3. **Export** as glTF Binary (`.glb`), with "Apply Modifiers" on, and no
   cameras or lights.
4. **Compress** (keeps the whole café under about 5 MB):

       npm run models:optimize -- room.glb public/models/room.glb --compress meshopt --texture-compress webp

   A file over about 2 MB after this usually has textures that are too
   large; resize them to 1024 px or less.
5. **Register** it in `lib/cafe/models.ts`:

       export const MODELS = { room: "/models/room.glb" };

   Names available: `room` (walls, floor, ceiling, lamps) and `brew-bar`
   (counter and espresso machine).
6. **Check** `npm run dev` → `/cafe`. If the file is missing or broken, the
   built-in piece shows and the console logs a `[cafe]` warning.

Keep `.blend` source files out of the repo.
```
